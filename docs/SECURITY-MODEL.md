# Security model

`X-User` identifies a requester but is not authentication. Any caller that can reach the API can impersonate a seeded user; the service is a take-home implementation, not a production identity system. Requests and bodies are untrusted. Group operations check membership, return 404 for nonmembers, and validate payer and participants. Only the payer can soft-delete an expense. A group-scoped unique constraint and transaction protect concurrent idempotency; monetary input is validated before storage. Browser origins are restricted by `CORS_ORIGINS`, which does not replace authentication. Local database credentials are development placeholders; secrets must remain outside source.
